## Dependency notes

- **002 → 003 is a hard chain, and it is a two-repo change.** The reason B is
  not a DSL-only strip: motion-spec `ir_gen` **reads** the acceleration-energy /
  per-axis `slv:AccelerationConstraint` / `AccelerationConstraintSpecification` /
  `PoseDiffEvaluator` / `control-signal` structures directly (ir_gen.py:768, 820-831,
  1030, 444/893/2262+) — it does not re-derive them. So the DSL emission cannot be
  removed until motion-spec derives the same structures.
- **002 (motion-spec)** ports the axis-enumeration decision table from the DSL's
  `controller_semantics.py` into a new `motion-spec/src/motion_spec/derive_solver.py`,
  reroutes `ir_gen` to build the IR from `algorithm + constraint + view`, and proves
  behavior preservation with an IR-equivalence test (full graph vs. stripped graph).
  **Blocked by P0**: `ir_gen` does not import today (`MJ` removed from `namespace.py`);
  fix that first.
- **003 (DSL strip)** is gated on 002's equivalence test being green on every example
  model. Stripping before 002 lands breaks the pipeline (empty solvers → dead codegen).
- **Deferred, not in these plans:** the Cartesian-force / joint-force output specs
  (`SLV.CartesianForceSpecification` / `JointForceSpecification` / `tau-*`). They sit on
  the spec/solver boundary and are lower value; kept untouched to bound blast radius.
